# Bubble Tea CN 常见问题解决方案

## 概述

本文档整理了 Bubble Tea CN 在开发、测试、部署过程中常见问题的诊断方法和解决策略。

## 开发问题

### 1. 程序无法启动

#### 问题描述

程序启动后立即退出或没有任何输出。

#### 诊断方法

```go
// 添加日志
func main() {
    log.Println("程序启动")
    
    p := tea.NewProgram(initialModel())
    log.Println("程序创建")
    
    finalModel, err := p.Run()
    log.Printf("程序运行完成: %v", err)
}
```

#### 解决方案

**原因 1**: 模型未正确实现 Model 接口

```go
// 错误：缺少方法
type model struct{}

func (m model) Init() tea.Cmd {
    return nil
}

func (m model) View() string {
    return "Hello"
}

// 缺少 Update 方法

// 正确：实现所有方法
type model struct{}

func (m model) Init() tea.Cmd {
    return nil
}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    return m, nil
}

func (m model) View() string {
    return "Hello"
}
```

**原因 2**: 输入输出配置错误

```go
// 错误：输入输出为 nil
p := tea.NewProgram(model,
    tea.WithInput(nil),
    tea.WithOutput(nil),
)

// 正确：使用默认输入输出
p := tea.NewProgram(model)
```

### 2. 终端显示异常

#### 问题描述

终端显示乱码、格式错误或无响应。

#### 诊断方法

```bash
# 检查终端类型
echo $TERM

# 检查终端颜色支持
tput colors
```

#### 解决方案

**原因 1**: 终端不支持 ANSI 转义序列

```go
// 检查终端支持
if !term.IsTerminal(os.Stdout) {
    log.Println("警告：输出不是终端")
}

// 使用备用屏幕
p := tea.NewProgram(model, tea.WithAltScreen())
```

**原因 2**: 终端类型设置错误

```bash
# 设置正确的终端类型
export TERM=xterm-256color

# 或
export TERM=xterm
```

### 3. 程序无响应

#### 问题描述

程序运行后无法响应键盘输入。

#### 诊断方法

```go
// 添加调试日志
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    log.Printf("收到消息: %T", msg)
    
    switch msg := msg.(type) {
    case tea.KeyMsg:
        log.Printf("按键: %s", msg.String())
        // 处理按键
    }
    
    return m, nil
}
```

#### 解决方案

**原因 1**: 输入通道阻塞

```go
// 错误：在 Update 中执行阻塞操作
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    time.Sleep(10 * time.Second) // 阻塞
    return m, nil
}

// 正确：使用命令异步执行
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    return m, tea.Tick(time.Second, func(t time.Time) tea.Msg {
        return TickMsg(t)
    })
}
```

**原因 2**: 消息通道满

```go
// 增加消息通道大小（如果需要）
p := tea.NewProgram(model)
// 注意：通常不需要修改默认大小
```

### 4. 内存泄漏

#### 问题描述

程序运行一段时间后内存占用持续增长。

#### 诊断方法

```bash
# 使用 pprof 分析
go tool pprof http://localhost:6060/debug/pprof/heap
```

#### 解决方案

**原因 1**: 命令未正确清理

```go
// 错误：命令创建后未清理
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    return m, tea.Every(time.Second, func(t time.Time) tea.Msg {
        return TickMsg(t)
    })
}

// 正确：使用上下文取消
type model struct {
    ctx    context.Context
    cancel context.CancelFunc
}

func (m model) Init() tea.Cmd {
    m.ctx, m.cancel = context.WithCancel(context.Background())
    return tea.Every(time.Second, func(t time.Time) tea.Msg {
        select {
        case <-m.ctx.Done():
            return nil
        default:
            return TickMsg(t)
        }
    })
}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.QuitMsg:
        m.cancel()
    }
    return m, nil
}
```

**原因 2**: 缓冲区未释放

```go
// 错误：缓冲区持续增长
type model struct {
    history []string
}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyMsg:
        m.history = append(m.history, msg.String())
    }
    return m, nil
}

// 正确：限制缓冲区大小
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyMsg:
        m.history = append(m.history, msg.String())
        if len(m.history) > 100 {
            m.history = m.history[1:]
        }
    }
    return m, nil
}
```

## 测试问题

### 1. 测试超时

#### 问题描述

测试运行超时或挂起。

#### 诊断方法

```go
func TestProgram_Run(t *testing.T) {
    // 设置超时
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    
    // 运行测试
    // ...
}
```

#### 解决方案

**原因 1**: 程序未正确退出

```go
// 错误：程序无限循环
type model struct{}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    return m, nil // 永远不退出
}

// 正确：处理退出消息
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg.(type) {
    case tea.QuitMsg:
        return m, tea.Quit
    }
    return m, nil
}
```

**原因 2**: 测试输入未正确设置

```go
// 错误：没有提供输入
p := tea.NewProgram(model)
p.Run() // 会挂起

// 正确：提供输入
p := tea.NewProgram(model,
    tea.WithInput(strings.NewReader("q\n")),
    tea.WithOutput(&bytes.Buffer{}),
)
p.Run()
```

### 2. 测试覆盖率不足

#### 问题描述

测试覆盖率低于预期。

#### 诊断方法

```bash
# 生成覆盖率报告
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

#### 解决方案

**原因 1**: 未测试所有代码路径

```go
// 添加测试用例
func TestModel_Update_AllCases(t *testing.T) {
    tests := []struct {
        name     string
        msg      tea.Msg
        expected tea.Model
    }{
        {"quit", tea.QuitMsg{}, &model{quit: true}},
        {"key", tea.KeyMsg{Type: tea.KeyEnter}, &model{enter: true}},
        {"mouse", tea.MouseMsg{}, &model{}},
    }
    
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            m := &model{}
            result, _ := m.Update(tt.msg)
            if !reflect.DeepEqual(result, tt.expected) {
                t.Errorf("Update() = %v, want %v", result, tt.expected)
            }
        })
    }
}
```

### 3. 并发测试失败

#### 问题描述

并发测试出现竞态条件或数据竞争。

#### 诊断方法

```bash
# 运行竞态条件检测
go test -race ./...
```

#### 解决方案

**原因 1**: 共享状态未正确同步

```go
// 错误：共享状态未同步
type model struct {
    count int
}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    m.count++ // 数据竞争
    return m, nil
}

// 正确：使用通道或互斥锁
type model struct {
    count int
    mu    sync.Mutex
}

func (m *model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    m.mu.Lock()
    m.count++
    m.mu.Unlock()
    return m, nil
}
```

### 3. 性能问题

#### 问题描述

程序运行缓慢或占用过多资源。

#### 诊断方法

```bash
# 使用 pprof 分析
go tool pprof http://localhost:6060/debug/pprof/profile

# 检查 CPU 使用
top -p $(pgrep bubbletea-cn)

# 检查内存使用
ps aux | grep bubbletea-cn
```

#### 解决方案

**原因 1**: 渲染过于频繁

```go
// 错误：每次更新都渲染
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    // 总是返回模型，导致重新渲染
    return m, nil
}

// 正确：只在需要时更新
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyMsg:
        m.input += msg.String()
        return m, nil
    }
    // 返回相同的模型，不重新渲染
    return m, nil
}
```

**原因 2**: View 函数过于复杂

```go
// 错误：View 函数执行复杂计算
func (m model) View() string {
    var s string
    for i := 0; i < 10000; i++ {
        s += "some text\n" // 低效的字符串拼接
    }
    return s
}

// 正确：优化 View 函数
func (m model) View() string {
    var b strings.Builder
    for i := 0; i < 10000; i++ {
        b.WriteString("some text\n")
    }
    return b.String()
}
```

## 终端问题

### 1. 终端状态未恢复

#### 问题描述

程序退出后终端状态异常（如光标隐藏、回显关闭）。

#### 诊断方法

```bash
# 检查终端状态
stty -a

# 重置终端
reset
```

#### 解决方案

**原因 1**: 程序异常退出

```go
// 确保资源正确清理
func (p *Program) shutdown(killed bool) {
    defer func() {
        if r := recover(); r != nil {
            // 恢复终端状态
            p.renderer.stop()
        }
    }()
    
    // 正常清理
    p.renderer.stop()
}
```

**原因 2**: 信号处理不当

```go
// 正确处理信号
func (p *Program) handleSignals() chan struct{} {
    ch := make(chan struct{})
    
    go func() {
        defer close(ch)
        
        sig := make(chan os.Signal, 1)
        signal.Notify(sig, syscall.SIGINT, syscall.SIGTERM)
        defer signal.Stop(sig)
        
        for {
            select {
            case <-p.ctx.Done():
                return
            case <-sig:
                p.Send(InterruptMsg{})
            }
        }
    }()
    
    return ch
}
```

### 3. 窗口大小变化未响应

#### 问题描述

调整窗口大小时程序未响应。

#### 诊断方法

```go
// 添加日志
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.WindowSizeMsg:
        log.Printf("窗口大小: %dx%d", msg.Width, msg.Height)
    }
    return m, nil
}
```

#### 解决方案

**原因 1**: 未处理窗口大小消息

```go
// 正确：处理窗口大小消息
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.WindowSizeMsg:
        m.width = msg.Width
        m.height = msg.Height
        return m, tea.ClearScreen
    }
    return m, nil
}
```

## 性能优化

### 1. 渲染性能

#### 问题描述

渲染速度慢，界面卡顿。

#### 解决方案

**优化 1**: 减少渲染频率

```go
// 使用帧率控制
p := tea.NewProgram(model, tea.WithFPS(30))
```

**优化 2**: 优化 View 函数

```go
// 使用字符串构建器
func (m model) View() string {
    var b strings.Builder
    b.WriteString("Header\n")
    b.WriteString(m.content)
    b.WriteString("\nFooter")
    return b.String()
}
```

**优化 3**: 缓存不变的部分

```go
type model struct {
    header string
    body   string
    footer string
}

func (m model) View() string {
    return m.header + m.body + m.footer
}
```

### 2. 内存优化

#### 问题描述

内存占用过高。

#### 解决方案

**优化 1**: 重用对象

```go
// 使用对象池
var bufferPool = sync.Pool{
    New: func() interface{} {
        return new(strings.Builder)
    },
}

func (m model) View() string {
    b := bufferPool.Get().(*strings.Builder)
    defer bufferPool.Put(b)
    
    b.Reset()
    b.WriteString("Content")
    return b.String()
}
```

**优化 2**: 限制缓冲区大小

```go
type model struct {
    lines []string
}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyMsg:
        m.lines = append(m.lines, msg.String())
        if len(m.lines) > 1000 {
            m.lines = m.lines[1:]
        }
    }
    return m, nil
}
```
